## CMS 的 12 项要求

| 要求           | 配置/本地数据到页面验证           | 真实远程验证                |
| -------------- | --------------------------------- | --------------------------- |
| 修改头像       | 图片字段、媒体路径与重新构建通过  | 待 GitHub 授权上传          |
| 修改简介       | JSON 字段与首页显示通过           | 待 CMS 保存                 |
| 修改邮箱       | 公开邮箱与 mailto 渲染通过        | 待 CMS 保存                 |
| 修改 GitHub    | 合法 URL 与前台链接通过           | 待 CMS 保存                 |
| 新增文章       | 内容集合、构建及公开详情通过      | 待 CMS 创建                 |
| 修改文章       | 修改后重建内容更新通过            | 待 CMS 编辑                 |
| 删除文章       | 删除后详情/RSS 消失通过           | 待 CMS 删除                 |
| 上传文章图片   | media 配置与本地图像路径/构建通过 | 待 CMS 真正上传             |
| 新增项目       | 项目集合、详情、链接、截图通过    | 待 CMS 创建                 |
| 修改项目       | 项目字段/Schema/页面映射已配置    | 待 CMS 修改往返             |
| 管理知识分类   | 自定义分类在本地构建后显示通过    | 待 CMS 保存分类             |
| 保存后自动部署 | push 工作流与构建门禁已配置       | 待仓库首次真实 Actions 运行 |

没有把“配置已完成”当作“云端操作已测试”。本地的上传测试是对图片文件与媒体路径的验证，而非对 GitHub 上传 API 的调用。

## 所有者需要完成

1. 创建或提供目标 GitHub 仓库，推送 `main`。
2. 仅授权 Pages CMS 访问该仓库，测试登录与保存。
3. 在 Settings → Pages 选择 GitHub Actions。
4. 对上表依次做一次 CMS 实际操作，并检查 GitHub 提交、Actions、线上页面。
5. 替换真实简介/头像/联系方式，删除或替换所有示例内容；确认没有把私密资料提交到公开历史。
6. 只有选定独立域名后才设置 DNS、CNAME 和仓库 URL/base 变量。

## 边界与非目标

- 无自建数据库、认证服务、私有知识库同步、付费会员、评论和分析脚本。
- 不假设现有 GitHub 用户名、域名、邮箱或社交账号。
- Google Fonts 等第三方字体服务不被请求；使用本地字体和中文系统回退。
- 仅静态托管；GitHub Pages 缓存策略无法通过本项目任意设置。
- 图片优化以合理尺寸、WebP/AVIF、延迟加载和布局稳定为基础；没有伪称 CMS 自动转码。
